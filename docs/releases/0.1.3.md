# Pari 0.1.3 alpha

Pari 0.1.3 alpha strengthens ingestion validation and reference-workload
consistency, and adds reproducible evidence from four public-corpus tracks.

## Installation

```sh
python -m pip install "pari-similarity==0.1.3"
cargo add pari-core@0.1.3 pari-index@0.1.3 pari-store@0.1.3
```

Python imports remain `import pari`. Keep all four public Rust crates on the
same release version. CLI archives, checksums, and the dependency SBOM are
attached to this release with GitHub build provenance attestations.

## Fixes

- Non-callable progress handlers are rejected before input inspection or batch
  ingestion. The convenience helper validates feature/progress values before
  creating a local index; existing memory and persistent contents are preserved.
- Dataset adapters reject boolean, fractional, and invalid batch sizes before
  importing optional libraries or reading a source.
- Explicit invalid backend values no longer silently select memory storage.
- Code-corpus verification rechecks cached sources and validates retained source
  snapshots before publishing outputs. Changed inputs roll back staged results.
- Checksummed benchmark evidence retains its original bytes across Windows and
  Unix checkouts and automatic formatting hooks.
- Published README documentation links target this release's tagged source.
  Version-specific badges avoid stale package-version images.

## Compatibility

Supported APIs, affine32/affine64 signature identities, `.pari` format version 1,
and CLI machine-output revision 1 retain their contracts. Public crates retain
Rust 1.81; the Python extension retains Rust 1.83 and CPython 3.10+ abi3 wheels.
The release inherits the existing 0.1.2 fixes.

This is an alpha release. The dedicated native-Linux 10M campaign still requires
its documented 128 GiB host; the out-of-core evaluation remains gated on that
evidence. See the [compatibility policy](https://github.com/dipeshbabu/pari/blob/v0.1.3/docs/compatibility.md).
