# Pari 0.2.0 alpha

Pari 0.2.0 alpha turns LSH candidates into ranked answers. Indexes can store
full signatures and return each candidate with its estimated Jaccard
similarity, deduplication can require a minimum similarity without a custom
callback, and a built-in shingling helper covers common text features.

## Installation

```sh
python -m pip install "pari-similarity==0.2.0"
cargo add pari-core@0.2.0 pari-index@0.2.0 pari-store@0.2.0
```

Python imports remain `import pari`. Keep all four public Rust crates on the
same release version. CLI archives, checksums, and the dependency SBOM are
attached to this release with GitHub build provenance attestations.

## Similarity-scored search

- Create an index with stored signatures:
  `Index.create(path, store_signatures=True)`,
  `PersistentIndexOptions::new().store_signatures(true)`, or
  `pari index --store-signatures`.
- Rank candidates with `Index.search_scored(sketch, min_similarity=..., top_k=...)`,
  `PersistentIndex32::query_scored`, or
  `pari search --scores --min-similarity 0.8 --top-k 10`. Results are sorted by
  estimated similarity, highest first, with ties broken by key.
- `signature(key)` returns a stored sketch and `stores_signatures` reports the
  setting. Scoring an index without stored signatures fails with a clear error.
- Signatures add `num_perm × 4` bytes per item (`× 8` for affine64). Queries read
  them lazily; reopening does not load them.

## Similarity floor for deduplication

- `deduplicate(..., min_similarity=0.9)`, `DedupeIndex(min_similarity=0.9)`, and
  `pari dedup --min-similarity 0.9` reject candidate pairs below the floor
  natively, before groups are joined and before any `exact` verifier runs.
- `DedupeIndex.similarity(left, right)` returns the estimate for two records.
- `pari dedup --emit pairs --min-similarity` reports each pair's similarity.

## Text features

- Experimental `pari.shingles(text, size=3, unit="word" | "char")` returns
  normalized word or character n-grams as bytes:
  `deduplicate(documents, feature=lambda text: shingles(text, 3))`.

## Fixes

- CLI commands exit cleanly when a downstream reader such as `head` closes
  stdout early, instead of panicking or reporting an error.
- `pari dedup --output` creates missing parent directories and names the output
  path when it cannot be created.
- Lazy readers, snapshot converters, external builds, and Datasketch imports
  gain stricter validation; see the changelog for details.

## Documentation

## Compatibility

Signatures are stored in new optional `Signatures` sections of `.pari` format
version 1. Files without them read and write exactly as before. Pari 0.1.x
readers skip the new sections; committing such a file with 0.1.x rewrites it
without signatures, after which scored queries report that signatures are
unavailable.

This is a minor release because public Rust types gained members:
`pari_format::SectionKind::Signatures`, new `pari_store::StoreError` variants
(`Signature`, `SignaturesUnavailable`, `InvalidScoreFilter`), and
`StoreStats::stores_signatures`. Code that matches these enums exhaustively or
constructs `StoreStats` literally needs updating. Python APIs, CLI commands,
JSONL input, and machine-output revision 1 remain compatible; new output fields
(`scores`, `similarity`, `stores_signatures`) appear only where documented.

Public crates retain Rust 1.81; the Python extension retains Rust 1.83 and
CPython 3.10+ abi3 wheels.

This is an alpha release. The dedicated native-Linux 10M campaign still requires
its documented 128 GiB host; the out-of-core evaluation remains gated on that
evidence. See the [compatibility policy](https://github.com/dipeshbabu/pari/blob/v0.2.0/docs/compatibility.md).
