# Pari 0.3.2 alpha

A persistent-index commit no longer silently overwrites a snapshot that
another handle or process committed after this handle opened it. Commits take
an operating-system lock on a sibling `<index>.lock` file, which exists only
while a commit runs. A stale handle's commit fails with `StorageError` (Rust:
`StoreError::Io`) and keeps its uncommitted changes in memory; reopen the index
to continue. This covers `Index`, `Index64`, `DedupeIndex(backend="local")`,
`PersistentIndex32`/`PersistentIndex64`, and `pari index`. See
[persistence](../persistence.md#writer-model).

Opened indexes now keep bucket directories on disk. Persistent indexes,
`ReadOnlyIndex`, `pari search --read-only`, and `pari verify` still validate
every directory when they open a snapshot, but retain about 4.6 bytes per
bucket instead of 56. On the dedicated 10M-item host, reopen memory growth fell
from 5.04 GB to 0.36 GB, reopen time fell from 6.43 s to 4.27 s (read-only) and
from 9.20 s to 6.93 s (persistent), and query latency and throughput did not
regress. Uncommitted inserts in persistent indexes also use less memory.

Rust adds `pari_format::BucketDirectory` and
`BucketDistribution::from_size_counts`. There are no incompatible API changes,
and the snapshot format is unchanged.

Install the Python package with `pip install pari-similarity==0.3.2` or
download a CLI archive from the
[GitHub release](https://github.com/dipeshbabu/pari/releases/tag/v0.3.2).
