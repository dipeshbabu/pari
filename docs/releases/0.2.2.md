# Pari 0.2.2 alpha

Pari 0.2.2 alpha fixes persistent indexes that could not be saved above about
3.7 million items, and adds the first validated 10M-item scale evidence.

## Installation

```sh
python -m pip install "pari-similarity==0.2.2"
cargo add pari-core@0.2.2 pari-index@0.2.2 pari-store@0.2.2
```

Python imports remain `import pari`. Keep all four public Rust crates on the
same release version. CLI archives, checksums, and the dependency SBOM are
attached to this release with GitHub build provenance attestations.

## Fixes

- **Large persistent indexes.** `PersistentIndex32`, `PersistentIndex64`,
  `Index`, `Index64`, `DedupeIndex(backend="local")`, and `pari index` failed to
  commit indexes above about 3.7 million items with `SectionTooLarge`, because
  all band hashes were written as one section above the format's 256 MiB
  section limit. Key metadata is now written as row-aligned `Keys`/`BandHashes`
  section pairs of about 64 MiB, and the persistent reader, lazy reader, and
  external builder read them. Indexes that fit in one pair are byte-for-byte
  unchanged, so existing files and older readers are unaffected. The fix was
  verified by a full 10M-item campaign.
- Release tooling refuses versions whose PyPI filenames are already used, and
  the PyPI recovery workflow can restore blocked wheels for any version.

## Scale evidence

The dedicated 10M campaign ran on a 12-vCPU, 130 GiB Linux host with local NVMe.
A 10M in-memory index peaks at 17.3 GiB, bytes per item stay at 440, and query
p99 stays below 0.005 ms. Persistent construction is the slowest phase (346 s,
36 GiB, single-threaded); the bounded external builder produces the same index
in 70 s. See [10M scale evidence and decisions](../scale-10m-evidence.md).

## Other changes

- The license copyright line names Dipesh Tharu Mahato as the sole copyright
  holder. Third-party notices are unchanged.
- `benchmarks/dedupe_memory.py` measures the high-level `DedupeIndex` memory
  model.

## Compatibility

No public API changes. Supported APIs, affine32/affine64 signature identities,
`.pari` format version 1, and CLI machine-output revision 1 retain their
contracts; large indexes now use the documented multi-pair key metadata layout
in format version 1. Public crates retain Rust 1.81; the Python extension
retains Rust 1.83 and CPython 3.10+ abi3 wheels.

This is an alpha release. See the
[compatibility policy](https://github.com/dipeshbabu/pari/blob/v0.2.2/docs/compatibility.md).
