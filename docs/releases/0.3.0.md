# Pari 0.3.0 alpha

Pari 0.3.0 completes the affine64 surface. The 64-bit MinHash family was previously a core primitive with no end-to-end path; this release carries it through indexing, persistence, the Python package, the CLI, and Datasketch interoperability as a supported interface. The release also adds Linux arm64 artifacts and a set of persistence-correctness and dependency-security fixes.

Affine32 remains the default on every interface. Its APIs, machine-readable output, and persisted bytes are unchanged.

## Install

Python 3.10 or newer:

```bash
python -m pip install "pari-similarity==0.3.0"
```

The distribution name remains `pari-similarity`; Python code continues to import `pari`.

Rust 1.81 or newer:

```bash
cargo add pari-core@0.3.0 pari-index@0.3.0 pari-store@0.3.0
```

The four public crates are released together. Add `pari-format@0.3.0` only when working directly with the codecs or persisted-format metadata.

Signed-tag release artifacts include CLI archives for Linux x86-64, Linux arm64, macOS arm64, and Windows x86-64, plus `SHA256SUMS`, a CycloneDX SBOM, and build provenance.

## Highlights

- `LshIndex64` provides batch-first candidate generation over full-width affine64 signatures, with the same deterministic grouping and query observability as the affine32 index.
- `PersistentIndex64` and `LazyIndex64` store affine64 snapshots through canonical reference and external builds. Format v1 is extended by explicit width identity, not by reinterpreting existing affine32 bytes.
- Python exposes explicit `MinHash64` and `Index64` types with full-width signature reconstruction, bounded batch construction, and local persistence. `MinHash` and `Index` remain affine32.
- The CLI accepts explicit affine64 indexing and deduplication, reconstructs full-width signatures through `MinHash64::from_signature`, and derives search, inspection, explanation, and verification from persisted metadata.
- The optional Datasketch 2.x adapter imports and exports affine64 signatures with full-width validation, covered by installed-wheel persistence tests and a semantics-matched affine32/affine64 benchmark.
- Release Validation builds a manylinux2014 aarch64 Python wheel, runs it on native Linux arm64, and packages a natively smoke-tested Linux arm64 CLI archive.
- An opt-in backend conformance kit lets third-party `StorageBackend` implementations reuse Pari's atomicity, query-parity, lifecycle, capability, and statistics contract tests without enabling Redis.
- Pinned pre-commit checks cover repository text and syntax policy, both Rust formatting workspaces, and workflow dependency pins without moving expensive protected-CI gates into the normal commit path.

## Correctness and security fixes

Users on 0.2.0 should upgrade. This release fixes:

- **Data loss on failed close.** Python index handles retained no pending changes when `close()` failed. Storage errors can now be resolved and the commit retried without losing data.
- **Lost query metrics.** Persistent indexes discarded query observations and accumulated counters across flush, sync, and commit retries.
- **Vulnerable IDNA resolution.** Redis's URL dependency now resolves to patched IDNA while retaining Rust 1.81, and dependency audits cover optional features.
- **Destination clobbering.** Initial persistent-index creation, lazy publication, and bounded external publication now atomically refuse occupied or concurrently created destinations and roll back transaction-owned outputs on failure.
- **Predictable temporary paths.** Persistent commits use uniquely owned temporary files instead of following or truncating a predictable sibling path.
- **Partial index publication.** `pari index` publishes its destination only after successful ingestion instead of leaving a valid-looking partial index behind.
- **Silent TTL loss.** Backend retention rejects values that cannot round-trip through whole-second Redis metadata instead of silently truncating or disabling TTL.
- **Unenforced benchmark timeouts.** Campaign stages enforce each profile's declared timeout and preserve the exact limit and partial logs in timeout failure evidence.
- **MSRV drift.** All non-Python workspace crates and the Criterion harness compile under Rust 1.81 again.

## Compatibility and migration

Supported 0.1 and 0.2 Python, Rust, CLI, signature, and `.pari` format-v1 behavior remains compatible. Existing affine32 code needs no changes to upgrade.

The affine64 surface moves from partial to supported. Width is selected by explicit type or explicit CLI/JSONL request; there is no mode flag that changes an existing type's width. `PersistentIndex32` and `LazyIndex32` accept only affine32 snapshots, and `PersistentIndex64` and `LazyIndex64` accept only affine64 snapshots. Builders preserve the source identifier and width rather than relabeling persisted band hashes.

CLI machine-readable output remains revision 1. Affine64 selection and the metadata-derived fields are additive, and existing fields keep their meaning and type. Consumers should continue to ignore unknown fields.

Rust applications should update `pari-core`, `pari-format`, `pari-index`, and `pari-store` together when more than one is used. Published inter-crate dependencies require the exact coordinated 0.3.0 version. The minimum Rust version for the public crates remains 1.81; the `pari-py` binding continues to declare and test Rust 1.83 for PyO3 0.29.

Datasketch interoperability remains opt-in and experimental. Pari and Datasketch use different default seed-to-permutation mappings and LSH implementations, so byte-identical default signatures and identical candidate sets should not be assumed at either width. Follow the [interoperability guide](../datasketch-v2.md).

The complete supported/experimental classification is in the [v0.x compatibility contract](../compatibility.md).

## Performance evidence

The committed scale envelope is unchanged. The selected [native-Linux 100K and 1M campaign report](../benchmark-evidence.md) remains the reference evidence for this release, and its recorded numbers apply only to the linked environment and workload. This release adds a semantics-matched affine32/affine64 Datasketch benchmark but does not re-baseline the campaign.

Affine64 doubles signature width. Expect proportionally larger signatures and persisted band-hash payloads relative to affine32 at the same permutation count. Choose the width from collision-resistance requirements rather than treating affine64 as a general throughput improvement.

## Experimental surfaces and known limits

- Planner coefficients and storage recommendations, the CLI `plan` and `explain` commands, optional Datasketch and dataset adapters, Redis namespace and descriptor bytes, observability measurement policy beyond supported fields, and direct `pari-store-lazy`/`pari-store-build` APIs remain experimental.
- The committed scale envelope is 1M items. This release makes no 10M, distributed sharding, GPU, out-of-core clustering, Weighted MinHash, or SimHash performance claim.
- Redis is a shared runtime backend rather than an archival format. Use the versioned `.pari` format for durable interchange.
- LSH results are approximate candidates. Applications that need an exact similarity threshold must retain or reconstruct source signatures and verify candidates.
- The experimental storage-backend crates are still not part of the published Rust set.

## Security and provenance

The release workflow builds and install-tests artifacts without publication credentials, publishes through short-lived PyPI and crates.io OIDC tokens, attests the assembled files, and creates the GitHub prerelease only after publication succeeds. Report vulnerabilities through GitHub's private process described in [SECURITY.md](../../SECURITY.md).
