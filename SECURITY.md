# Security policy

## Supported releases

The latest published 0.x release receives security fixes. Older 0.x lines may be superseded rather than patched in place; release notes identify the supported replacement. `main` is development code, not a published support line.

## Report privately

Use GitHub's **Security → Report a vulnerability** form. Private vulnerability reporting is enabled. Include affected versions, impact, reproduction details, and suggested mitigation.

Do not open a public issue, pull request, or discussion containing exploit details before coordination. The maintainer will acknowledge the report, assess affected releases, coordinate a fix/advisory when warranted, and keep status in the private thread.

Security fixes preserve compatibility where safe. If safety requires a break, the advisory and release notes explain migration. Published tags and package versions remain immutable; remediation uses a new release.
